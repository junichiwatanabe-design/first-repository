# first-repository

特定の Google ドライブフォルダにある複数のスプレッドシートファイル（ファイル名に日付を含む、案件ごとの帳票）から、
指定した起点日付を基準に5日分の案件を抽出し、集計用スプレッドシート内に「1案件＝1タブ」として
書き出す Google Apps Script（GAS）プロジェクト。Google Sheets には保存される改ページ機能が無いため、
印刷時に案件単位で改ページされるよう、案件ごとに別タブへ分けている。

## 構成ファイル

- `Code.gs` — メインロジック
- `appsscript.json` — GAS マニフェスト（タイムゾーン、必要スコープ）
- `.clasp.json` — [clasp](https://github.com/google/clasp) 用設定。`scriptId` は実際の
  Apps Script プロジェクトの ID に書き換えてください

## セットアップ

1. 集計に使いたい Google スプレッドシートを開き、拡張機能 > Apps Script でスクリプトエディタを開く
2. このリポジトリの `Code.gs` と `appsscript.json` の内容をコピーし、スクリプトエディタ側の
   `コード.gs` / `appsscript.json` に貼り付ける（もしくは `clasp` で `.clasp.json` の
   `scriptId` を書き換えた上で `clasp push`）
3. 対象スプレッドシートを開き直す（または再読み込み）と、メニューに「日次データ取込」が追加される

## 使い方

1. 初回実行時、自動的に「設定」という名前のシートが作成される（作成直後は入力を促すアラートが出て処理は中断する）
2. 「設定」シートに以下を入力する

   | セル | 内容 | 例 |
   |------|------|----|
   | B1 | 対象フォルダの URL または フォルダID | `https://drive.google.com/drive/folders/xxxxxxxx` |
   | B2 | 各ファイル内で読み込む固定タブ名 | `Sheet1` |
   | B3 | 起点日付 | `2026/07/13` |
   | B4 | 読み込み日数（1〜5、空欄で5日） | `3` |
   | B5 | ラベル出力先スプレッドシートの URL または ID（自動設定・空欄でOK。既存のスプレッドシートを使わせたい場合は手動で貼ってもよい） | （未入力のまま、または `https://docs.google.com/spreadsheets/d/xxxxxxxx/edit`） |

3. メニュー「日次データ取込」→「5日分読み込み実行」を実行する
4. 起点日付から連続N日分（起点日を含む、B4で指定した日数。未入力なら5日）について、
   フォルダ内のスプレッドシートファイルのうちファイル名にその日付（`yyyy.M.d` 形式、例: `2026.7.13`）
   を含むものをすべて検出し、各ファイルの指定タブのデータ（使用済み範囲全体）を読み込む
5. マッチした案件（ファイル）ごとに、集計用スプレッドシート内に個別のタブを作成する。
   タブ名は「日付 + 企業名」（例: `2026.7.15 APPREA`）。企業名が読み取れない場合はファイル名を使う。
   同じ日付のタブは実行のたびに一旦すべて削除してから作り直すため、再実行しても重複・古いタブが残らない
6. 各タブは元の案件ファイルのタブを `copyTo()` でそのまま複製したもので、
   フォントの種類・サイズ・太さ、背景色、罫線、セル結合、列幅、非表示列など
   元シートの書式を一切変更せずそのまま引き継ぐ。ただし「メニュー名」「数量」列の
   データ行（見出し行を除く）だけはフォントサイズを14ptに設定する（太字・背景色などは変更しない）
   - セルの中身は、コピー前に評価済みの値で上書きする（数式としてはコピーしない）。
     元シートが他シート参照などの数式を含んでいても、コピー先で参照が切れて
     `#REF!` のようなエラーになることを防ぐため
7. 印刷する際は、複数タブを選択して「ファイル > 印刷 > 選択したシート」から一括印刷すると、
   タブ（＝案件）の境目で自動的に改ページされる
8. 実行完了後、日付ごとの該当ファイル数・作成タブ数・タブ名・警告（タブが見つからない、企業名が空、
   処理中にエラーが発生した等）がダイアログで表示される。案件1件分の処理は個別に例外を捕捉しているため、
   ある案件の処理でエラーが起きても他の案件・他の日付の処理は継続される

## 印刷用ラベルの作成

「設定」シートを除く現在存在する案件タブごとに、日付・企業名・メニュー名・数量を集めて、
ラベル専用の別スプレッドシート内に案件と同名のタブを作り、A4・24面（3列×8行）の
ラベルシールに印刷できる形式で出力する機能。

1. メニュー「日次データ取込」→「印刷用ラベル作成」を実行する
2. 初回実行時、ラベル専用の新しい Google スプレッドシート（名前は
   「（集計用スプレッドシート名）（ラベル印刷）」）が集計用スプレッドシートと同じ
   フォルダに自動作成され、その ID が「設定」シートの B5 に保存される
   （2回目以降はこの ID のファイルを再利用する。B5 は空欄のままでよい）
3. 各案件タブのメニュー表を走査し、メニュー名・数量がある行だけをラベル1件として集計する
   （複数の案件タブ＝複数日分をまとめて処理する）
4. ラベル専用スプレッドシート内に「案件タブと同名のタブ」を1つずつ作成する
   （既に同名タブがあれば削除してから作り直すため、再実行しても古い内容が残らない。
   案件が無くなった場合、対応するタブも自動的に削除される）
5. 各案件タブ内では、1件につき縦に隣接する2行を使って同一内容を2枚配置する
   （3列×8行＝24枚＝12件で1ページ。13件目以降は次の8行ブロック＝次ページに続く）
6. 各ラベルは3段のセル（縦に3行分）で構成される
   - 1段目: `日付　企業名`（左寄せ。日付はゼロ埋めなし・年なしの `M/d` 形式、例: `7/16`。
     元の値が `2026.7.16` や `2026/7/17` のように年付き・区切り文字違いでも
     `7/16` の形に統一される。折り返さず、はみ出したら途中で切れる）
   - 2段目: メニュー名（左寄せ・フォントサイズは1段目より2pt小さい。折り返さず、
     はみ出したら途中で切れる。中央寄せだと先頭が見えず分かりにくいため左寄せにしている）
   - 3段目: 数量（中央寄せ。太字・大きめフォントで強調。はみ出したら途中で切れる）
   3段とも行の高さは常に固定（データの長さによって自動で広がらない）
7. 列幅66mm・ラベル1枚あたりの高さ33.9mm（A-one マルチプリンタ用ラベルシール24面の実寸、
   3段の高さ内訳は34px/44px/50px。数量段を6px減らしメニュー名段に6px足している）で
   列・行のサイズを設定する。お使いのラベルシート商品の実寸がこれと異なる場合は、
   `Code.gs` の `LABEL_COL_WIDTH_MM` / `LABEL_SUBROW_HEIGHTS_PX` を実際の値に合わせて
   調整する（`LABEL_SUBROW_HEIGHTS_PX` の合計がラベル1枚の高さ（px）になる）
8. 印刷前に、ラベル専用スプレッドシートを開き、ファイル > 印刷でページの余白を
   上下約12mm・左右約5mm程度に設定し、拡大縮小は「なし（実際のサイズ）」にする。
   ラベル8枚分の高さは271.2mm（33.9mm×8）でA4の縦297mmとの差は25.8mm（片側12.9mm）
   しかないため、上下13mmちょうどだと0.2mm足りず最後の行が2ページ目にはみ出すことがある。
   12mm程度に少し余裕を持たせるとよい。それでも収まらない場合はさらに1〜2mm狭める。
   まず普通紙に試し印刷し、現物のラベルシートと透かして位置がずれていないか確認してから
   本番のラベルシートに印刷することを推奨する
   - 最終ページで3列中1〜2列しか埋まらない場合でも3列とも印刷範囲に含まれるように
     しているが、それでも位置がずれる場合は印刷ダイアログの「書式設定 > 配置」が
     「中央」になっていないか確認し、「左」に変更する
9. 完了ダイアログには、作成した案件数・メニュー件数・ラベル専用スプレッドシートの
   URL が表示される

## 注意事項

- フォルダ内のファイルはすべて Google スプレッドシート形式であることを前提としている
- 集計用スプレッドシート自身が対象フォルダ内にある場合、自分自身は読み込み対象から自動的に除外される
- ファイル名の日付形式は `yyyy.M.d`（月日ともにゼロ埋めなし）を前提としている。異なる形式を使う場合は
  `Code.gs` の `formatDateForMatch_` を変更する
- 案件タブは元ファイルのシートを `copyTo()` で複製したものなので、フォント・サイズ・太さ・
  背景色・チェックボックス・行の交互背景・列幅・非表示列などの見た目は元ファイル側の
  書式がそのまま反映される（集計側では一切変更しない）
